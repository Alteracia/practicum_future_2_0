# Роадмап трансформации на 12 месяцев

М1 — первый месяц после утверждения старта; дата среза радара не означает фактическое начало миграции. Условные календарные месяцы позволяют сохранить план при изменении даты старта.

## Целевые результаты и ограничения

К концу М2 согласованы архитектура, границы доменов и проекты каждого домена. К концу М12 работает промышленный портал, сотрудники подключённых доменов создают отчёты по разрешённым данным, новые бизнес-функции не добавляются в DWH. Остаток легаси разрешён с владельцем, мерами сопровождения и сроком вывода.

В контур портала входят разрешённые финансовые, кадровые, инвентаризационные и операционные показатели. Медкарты, истории болезни, снимки и результаты исследований не выгружаются в бизнес-lakehouse, включая промежуточные слои. Данные для ИИ обслуживаются отдельным контуром.

Обследование → принятые границы и политики → проверенная платформа → проверенные продукты → пилот портала → расширение → промышленная приёмка.
Работы могут перекрываться на стендах, но реальные данные допускаются только после проверки П2.
П4 не блокирует MVP: до переноса операционных функций продукты могут формироваться разрешёнными выгрузками из легаси.

FTE — эквивалент полной занятости. Это оценка потребности, не текущий штат. Люди платформы, DBA, BI и QA переиспользуются; строки нельзя механически складывать. На П1 руководители составляют календарь загрузки, особенно для пересечений П2/П3 и П3/П4. Если ресурса не хватает, уменьшается количество мигрируемых операционных функций, сохраняя срок портала и его проверки безопасности.

## Ресурсы инфраструктуры и бюджет

До обследования неизвестны объём разрешённой аналитики, интенсивность изменений и нагрузка. Сотни ТБ из исходного DWH не равны объёму переноса: медицинские данные исключены из аналитического контура.

На П1 рассчитываются:
- хранилище = разрешённые исходные данные + рост за год + преобразованные слои + снимки таблиц + независимые резервные копии; коэффициенты подтверждаются пилотом;
- сеть = объём начальной загрузки / допустимое окно + текущий поток изменений, с запасом по результатам теста;
- compute = ресурсы, обеспечившие принятый p95 при целевой конкуренции, плюс проверенный резерв на отказ;
- годовая стоимость = облако + лицензии/поддержка + трафик + трудозатраты + период параллельной эксплуатации.

На П2 выделяются три среды, изолированные доменные сети, отдельный контур ИИ, резервная площадка и лимиты расходов. Реальные размеры VM, дисков и NAT фиксируются после измерения и реализуются в Task4. Kubernetes и брокер не вводятся только ради масштабирования: их необходимость требует отдельного решения.

## Правила переключения и отката

1. До изменения фиксируются владелец записей, контрольные суммы, backup, окно работ и ответственный за решение.
2. Новая функция сначала работает на стенде и в сравнительном режиме без независимой двойной записи.
3. После приёмки переключается ограниченная группа; наблюдаются ошибки, задержки и сверки. Старый маршрут сохраняется до конца окна наблюдения.
4. При ошибках останавливаются новые записи затронутой функции, сохраняется журнал изменений, переносится дельта в выбранный источник истины и выполняется сверка. Только после этого возвращается старый маршрут.
5. При сбое аналитики операции продолжаются; отчёт показывает время последнего обновления. При сбое ИИ врач продолжает работу без рекомендаций ассистента.
