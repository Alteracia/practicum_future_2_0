# Проектирование целевой архитектуры
![C4 one Year.drawio.png](C4%20one%20Year.drawio.png)

## Как предложенная схема поддерживает ключевые сценарии:
1. Быстрая подготовка отчётности. Отчёты строятся не по сырым таблицам DWH с трансформациями «на лету», а по курированному слою lakehouse через портал — часы превращаются в минуты.
2. Независимое развитие финтеха и ИИ. У каждого домена своя БД и своя логика; наружу — только data‑продукт. Финтех может релизиться хоть каждый день, не согласовывая изменения с ИИ‑доменом или клиниками.
3. Масштабирование для новых бизнесов. Фармкомпании и производитель электроники подключаются как новые домены по тому же контракту, не трогая DWH и не требуя новой центральной логики.
4. Целостная картина по KPI при автономности доменов. Каталог и портал агрегируют data‑продукты всех доменов в общие показатели, даже когда домены развиваются независимо.
5. Закрыто требование: медкарты, истории болезни и результаты исследований остаются в домене «Клиники» / хранилище ИИ‑сервисов и не публикуются как data‑продукт в витрину.
